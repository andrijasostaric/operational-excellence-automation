# Current-State Assessment

## Process today

1. Business requester emails Procurement / Operations.
2. Vendor information arrives in inconsistent formats.
3. Risk and compliance checks are requested manually.
4. Approvals are tracked across email threads.
5. Finance / Operations creates the vendor record after approval.
6. Supporting evidence is saved in multiple locations.

## Pain points

| Problem | Operational impact | Risk / control impact |
|---|---|---|
| Inconsistent intake | Rework and delays | Missing mandatory information |
| Email-based approvals | Slow follow-up | Weak approval traceability |
| No shared status view | Repeated status requests | Limited oversight |
| Manual hand-offs | Increased cycle time | Steps can be skipped |
| Scattered evidence | Time spent searching | Audit readiness weakened |
| No exception dashboard | Issues discovered late | Weak management visibility |

## Root causes

- No single intake standard.
- Ownership changes between functions without explicit hand-off rules.
- Approval criteria are not embedded in the process.
- Workflow status is not system-driven.
- Evidence retention is treated as an administrative afterthought.

## Improvement hypothesis

A structured intake form, workflow-based routing, defined approval logic and central evidence record should reduce avoidable manual coordination while improving control visibility.
