# Implementation Plan

## Phase 1 — Discover
- Map current process and hand-offs.
- Confirm stakeholders and control owners.
- Capture baseline cycle time, rework and exception data.
- Identify mandatory legal, compliance, security and finance checks.

## Phase 2 — Design
- Define future-state process and RACI.
- Agree risk-tier logic and approval rules.
- Define exception handling and escalation.
- Design reporting and evidence-retention requirements.

## Phase 3 — Build and test
- Configure intake and workflow logic.
- Test normal, rejected, incomplete and high-risk scenarios.
- Validate permissions and evidence capture.
- Run user acceptance testing with representative stakeholders.

## Phase 4 — Pilot
- Launch with a limited set of new vendor requests.
- Monitor defects, delays and user feedback.
- Compare pilot performance against baseline.
- Adjust routing, notifications and instructions.

## Phase 5 — Roll out and improve
- Extend workflow to all in-scope requests.
- Publish operating guidance and ownership model.
- Review KPIs monthly.
- Maintain a backlog of process improvements.

## Change considerations

Success depends on more than automation. Users need clear instructions, owners need to understand their approval responsibilities, and management needs visibility of exceptions so the workflow becomes the normal way of working rather than another optional tool.
